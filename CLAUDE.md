# CLAUDE.md

Context for Claude working in this repo.

## What this is

A personal multi-game card-collecting web app, hosted on GitHub Pages, played hot-seat or with friends online (rooms in a Firebase Realtime Database). Ships with Sushi Go! Party, Sea Salt & Paper, 7 Wonders (base + Leaders, Cities and both Babel modules), 7 Wonders Duel (+ Pantheon and Agora), Air, Land & Sea (+ Spies, Lies & Supplies and Epic Mode), Set (all 16 variants, solo / shared-screen), Machi Koro (Machi Koro 2 + the original base game with its Harbor and Millionaire's Row expansions), and Jaipur (2 players, trained easy / normal / hard AI). No backend.

## Tech stack (locked)

TypeScript, Vite, React 19, Zustand for state, Firebase Realtime Database + anonymous Auth for online play (project `github-games-e7c7d`, shared with Kyle's other game sites — this app's data lives under `/card-collecting`), Vitest for tests. No server code of our own: GitHub Pages hosts the static site, Firebase holds the rooms, and the only server-side logic is the security rules in `database.rules.json`.

## Architecture

Five layers, separated by directory:

- **`src/core/`** — `GameModule<S, A, C>` contract, seeded RNG (mulberry32 in `rng.ts`), shared types (`Seat`, `PlayerId`, `GamePhase`). Game-agnostic — never references a specific game.
- **`src/games/<id>/`** — one folder per game. Each folder owns its own types, reducer (`applyAction`), AI, and UI bundle. Registered in `src/games/registry.ts`.
- **`src/net/`** — the room transport: `transport.ts` (the `RoomTransport` / `RoomConnection` interface, log-slot encoding), `firebaseRoom.ts` (the Firebase implementation, lazy-loaded), `fakeTransport.ts` (in-memory server for tests); `identity.ts` (localStorage UUID + saved name + room codes, `?fresh` escape hatch), `roomLink.ts` (`?room=CODE` in the URL), wire types (`types.ts`). Never imports from `src/store` or `src/ui`.
- **`src/store/`** — Zustand stores (`gameStore`, `networkStore`) + `actionSync.ts`. `gameStore` holds the active module + state and exposes `dispatch` (applies, then hands the move and the state before it to the registered broadcast handler), `applyLocal` (silent receiver path; false when the reducer rejects) and `restoreState` (online rollback).
- **`src/ui/`** — Game-agnostic shell: `App.tsx` (route between picker / lobby / playing), `GameLobby.tsx` (seat builder + game's `LobbyConfig`), `GameHost.tsx` (mounts the active game's `GameView`). Also the pieces game views share: `RulesBook.tsx`, and `MatchCharts.tsx`, the post-game "Match stats" panel (`StatsTabs`: tabs + a Chart / Table switch, so no value is hover-only) and its dependency-free SVG charts (`MultiLine`, `GroupedBar`, `StackedBar`, `HBarGrouped`, `Pie`; they measure their own width, take negative values and per-category `notes`). Colors and ink come from the `--mc-*` properties on `.match-stats` (theme.css), which a dark game-over screen overrides (Jaipur does). Sushi Go and Jaipur derive their stats in a pure `stats.ts` (tested) and lay the tabs out in `StatsPanel.tsx` (not `Stats.tsx`, which would collide with `stats.ts` on case-insensitive file systems); SSP's are worked out in its `ui.tsx` (`MatchStats`).
- **`src/ai/`** — Game-agnostic pieces for learned agents that act over a fixed action-slot space + legality mask: `masked.ts` (masked argmax / uniform / softmax sampling) and `mlp.ts` (dependency-free dense-network runtime for exported policy files, format `card-collecting/mlp@1`: layers of `act(W·x + b)`, W row-major [out][in] as base64 little-endian float32 — PyTorch `nn.Linear` layout).

Outside `src/`: **`training/`** — offline, never shipped. Headless match simulator, seat-swapped eval harness, a vectorized env server, and the Python (PyTorch) trainer + evaluator that drive it over stdio. Bundled to `training/dist/` (git-ignored) by `npm run train:build`. Runs live in `training/runs/<game>/<run>/` (git-ignored; `ssp/main` produced the shipped SSP levels) — give each game's trainer its own `<game>` folder as its default `--runs-dir`. See `training/README.md`.

## GameModule contract

The single rule that makes the multi-game design work:

```ts
GameModule<S, A, C> {
  id, name, tagline, minPlayers, maxPlayers, onlineSupported?, replayInLobby?, hiddenInfo?
  defaultConfig(seats) → C
  validateConfig(config, seats?) → string[]   // seats = the lineup about to start
  createInitialState(config, seed) → S
  applyAction(state, action) → S          // pure, deterministic
  chooseAIAction?(state, playerId) → A | null
  aiDelayMs?(state) → number              // AI pacing when a human is watching
  prepare?(config, seats) → Promise<void>  // async setup before a match (e.g. fetch AI policies)
  ui() → Promise<{ LobbyConfig, GameView, Rules? }>   // lazy-loaded
}
```

`aiLevels?` / `defaultAiLevel?` list the strengths an AI seat can play at (easiest first; default = the last). With two or more, both lobbies give every AI seat its own picker (`AiLevelSelect` in `lobbyParts.tsx`) and store the choice in `seat.aiLevel` (the one game-agnostic seat field for it), so the module's AI reads it back off `state.seats` and `prepare(config, seats)` loads every level in play. `src/core/seats.ts` has the shared helpers: `seatAiLevel` / `aiLevelsInPlay`, plus `nextSimultaneousSeat` / `sharedDeviceHumans` for simultaneous decisions (below). Sushi Go, SSP and Jaipur set them; their configs no longer carry a level.

`LobbyConfig` gets `{ config, seats, onChange, readOnly? }`. `readOnly` is set on an online guest's device, which shows the host's options inside a disabled fieldset: skip anything only the AI-driving device needs (Jaipur, SSP and Sushi Go don't prefetch their AI policy files then).

`prepare` runs on the device that drives the AI (local play, online host): the lobby awaits it on Start (the button shows "Loading AI…") and `GameHost` on Play again. After it resolves, `chooseAIAction` must answer synchronously — the AI driver only re-runs on state changes, so returning null while "not ready" would stall the match.

**Hard invariants every module must uphold:**
- `applyAction` is pure. No `Date.now`, no `Math.random`, no I/O. RNG draws from `state.rngState`.
- Randomness chosen by the acting player (deals, draws) is folded into the action payload so every device reduces identically.
- `createInitialState(config, seed, seats)` is pure: online, every device builds the opening itself from the room's start record.
- `S`, `A` and `C` are JSON-serializable — actions are logged as JSON, the config travels as JSON, and every device's state must come out equal.
- Every device holds the full state; hidden-information rules (other players' hands) are a UI concern. Friends-only honor, no anti-cheat.

The shell, store, and net layer never name a specific game. Adding a new game means: drop a folder, register it, done.

`onlineSupported: false` opts a module out of the online path — the lobby hides "Host online" for it. Only Set sets it (its claims are a shared card-by-card selection; see "Set online racing" below). An online room can't switch to such a game either. Default is `true`/absent.

`hiddenInfo: false` marks a game with nothing hidden (every card and coin public): hot-seat play skips the "pass the device" screen between human turns. It may also be a function of the match state, `(state) => boolean`, for games whose options add hidden information (read in `GameHost`). Machi Koro sets it to false; 7 Wonders Duel to a function — false for the base game (its face-down pyramid cards are hidden from both players alike), true with Pantheon or Agora (Conspiracies, Divinities placed face down, private draws).

`aiDelayMs(state)` overrides the AI driver's 380 ms wait before an AI move in matches with a human seat (all-AI matches stay at 80 ms), so a game can give its animations time to land. Machi Koro waits ~1.3 s before an AI builds after rolling (dice + coin flights) and ~0.75 s before it rolls; 7 Wonders Duel ~0.9 s before an AI takes a card.

`replayInLobby: true` makes the game-over "Play again" return to the lobby with the finished match's config and seats pre-filled (so options can change before re-dealing) instead of re-dealing at once. Online, the host's Play again takes the whole room back to its lobby (the room keeps the options). Only Sushi Go sets it (so the menu can change between matches).

## Multiplayer model

- **Firebase Realtime Database** (instance `github-games-e7c7d-default-rtdb`, web app "Card Collecting") via the Firebase JS SDK: one WebSocket on port 443, so it works on cellular and locked-down networks. It replaced peer-to-peer WebRTC (Trystero), which never connected reliably (strict NAT with no TURN server, flaky trackers, phones dropping sockets in the background) — the same move the Catan project made; this design is ported from it. The SDK loads lazily (`import('@/net/firebaseRoom')` from `networkStore`, its own ~77 KB gzip chunk); `warmUpNetwork()` starts it (and the sign-in) when an online box gets focus or the pointer. Solo / hot-seat play never downloads it or holds a connection: the transport `goOffline`s whenever no room is open.
- **Shared database.** Several web apps (Catan, Tractor, …) use the one database, so everything this app stores is under one top-level key, `DB_ROOT = 'card-collecting'` (`firebaseRoom.ts`; every path below is relative to it), and `database.rules.json` defines only that key (root `.read` / `.write` stay false). A database has a single rules set, so a plain deploy would wipe the other apps' rules: `firebase.json`'s predeploy hook runs `scripts/merge-db-rules.mjs` (copied from catan), which reads the live rules, replaces only the keys our file defines and deploys the merged `.firebase/database.rules.deploy.json` (git-ignored); it refuses to deploy if the live rules can't be read.
- **Keep usage small.** The database bills bytes stored and downloaded plus open connections (free plan: 1 GB stored, 10 GB/month downloaded, 100 simultaneous connections — shared by every app on the database), not reads or writes. Every device downloads every move of the current match and a rejoin downloads its whole log, so payloads carry only what devices read: the start record is `createInitialState`'s inputs (~0.5 KB, not the state), a move is `{"a": action, "n": 8-char nonce}`.
- **Identity**: each device signs in **anonymously and silently** (no visible login, account or email). The uid exists only so the rules can tie writes to a device. Seats belong to the `localStorage` UUID (`card-collecting.uuid`); an online human seat's `id` *is* its owner's UUID (so it's the `PlayerId` in game state), AI seats are `ai-N`. `?fresh` puts the UUID and the sign-in in `sessionStorage`, so two windows of one incognito session are two devices. The display name is saved too (`card-collecting.displayName`).
- **Room layout** (`rooms/{CODE}`, header of `src/net/firebaseRoom.ts`): `meta` (host uuid / uid, createdAt, `build`, protocol `v`), `lobby` (JSON string of `LobbyState` = `gameId`, `configJson`, `seats`, `match` (the match being played, null in the lobby), `matchCount`; edited by transaction), `matches/m{N}/start` (`StartRecord`: `gameId`, `configJson`, `seed`, `seats`, `hostUuid`, `startedAt`, `check`sum of the built opening; write-once, host only), `matches/m{N}/actions/aNNNNNN` (write-once log slots), `chat/`, `presence/` (`{ uid, uuid, name }` per connection, removed by `onDisconnect`). Payloads are JSON strings because the database drops empty arrays / objects and turns arrays into keyed objects. Written with each room: `roomDays/{day}` → when that UTC day ends (readable, no codes) and `roomIndex/{day}/{CODE}` → true (readable only a week after the day ends), so each new room's host sweeps the `SWEEP_DAYS` oldest days that ended over a week ago, deleting their rooms nobody is in, then the emptied days. (Day buckets because rules can't range-check a query's bounds: the earlier time-sorted index guarded by `query.endAt <= now - week` was refused outright, so nothing was ever swept.)
- **Rules** (`database.rules.json`; `firebase.json` / `.firebaserc` point at the project; deploy with `npm run deploy:rules`, which merges into the live rules — see above): signed-in devices read a room by its code (no listing); a room can be created over a free code only (a taken code makes the host try another); a room over a week old that nobody is in can be deleted by anyone; a day can't be backdated (so younger codes stay private); `meta` is never rewritten; anyone in the room edits the lobby; a match's `start` once, by the host's uid; its log slots once each, only after its start; chat once per id; presence only by its own uid; size caps everywhere. Changing the layout means bumping `PROTOCOL_VERSION` and the `v` check in the rules together.
- **The action log is the source of truth.** Every device runs `createInitialState(JSON.parse(configJson), seed, seats)` and applies the match's log in slot order, so all devices reduce identically; one whose opening doesn't match `check` (another app version) gets a chat warning. `ActionSync` (`src/store/actionSync.ts`): your own move applies at once and goes in a pending queue; the head is written to the next free slot with a transaction (`applyLocally: false`, so the log listener is how even the author learns the order). When the slot comes back as yours it's confirmed; when another device's move took it (simultaneous picks, two people clicking one Continue), the device restores `pending[0].before`, applies theirs, and replays its own on top: still-legal moves are rewritten, the rest dropped with a notice ("…went through first, so yours was taken back"). Rules refusals roll the move back; network failures retry. A spectator's `dispatch` is refused (gameStore's dispatch guard, registered by networkStore; `GameHost` also no-ops it).
- **Lobby** (`OnlineLobby.tsx`): edits are transactions, so guests seat themselves (on join, while `seats.length < maxPlayers` and no match is on; otherwise they watch, with a "Take a seat" button) even while the host's phone sleeps. Each player renames / recolors their own seat (`editSeat`; a taken color swaps); the host picks the game (any `onlineSupported` module — the room isn't tied to one), its options (`hostSetConfig`; guests see the game's `LobbyConfig` read-only), adds / removes AI seats, removes seats, and starts (`hostStartMatch`: `prepare`, then a transaction sets `match` atomically with the final seats, then the start record). `lobbyStartProblem` gives the seat-range / `validateConfig` reason a start is refused. A local lobby's "Host online" carries its options and AI seats into the new room (`createRoom(gameId, name, { config, seats })`).
- **Matches**: Play again (host) is a new match (`hostPlayAgain`: next `m{N}`, fresh seed, same lobby); the host's Lobby button (and Play again for `replayInLobby` games) sets `match` to null and every device goes back to the lobby. Devices watch only the lobby's current match (`followMatch`).
- **Joining** (`networkStore.joinRoom`): looks up `meta` (a definite "no room with code X" at once, or `unreachable` after a 15 s timeout, with Try again), takes a seat while the lobby is open, then replays the current match if one is on. Role: host uuid → host (a reloading host is the host again, re-runs `prepare` with `gameStore.aiReady` false until it resolves, and keeps running AIs); a seat in the match → guest; else spectator. Devices on another `build` than the room's (`__APP_BUILD__`, the commit on CI) get a chat warning. The code rides in the URL (`?room=ABCD`): a reload or an invite link ("Copy invite link") rejoins automatically when a name is saved (`useRejoinFromUrl`), else the picker's join box is prefilled. While a device is in a room, `App` routes by `networkStore.connection` (connecting / error card, `OnlineLobby`, `GameHost`); leaving lands on the picker.
- **Presence / disconnect**: `people` / `onlineUuids` come from `presence/`. Offline human seats show in the lobby and as an "X offline" pill in-game; this device's own lost link shows a "Reconnecting…" banner after 2 s, and its moves queue until the SDK reconnects.
- **AI in online**: one device runs `chooseAIAction` — `networkStore.aiDriver`: the host while it's connected, else the first connected seated human in seat order (a stand-in), and the host again when it returns. Every device derives it from presence (`aiDriverUuid` / `updateAiDriver`), so they agree; a device other than the host waits for its first presence snapshot before claiming it, and whoever takes it runs the module's `prepare` first (`ensureAiPrepared`, `gameStore.aiReady` false meanwhile). Spectators never drive. While it changes hands two devices may briefly both move an AI: the log keeps the first, and the other's move is dropped quietly (`dispatch(action, { ai: true })` marks AI moves; `ActionSync` carries `quiet` through replays and `dropped`). A stand-in shows a "running the AI" pill and a chat line. `GameHost.tsx`'s AI driver fires when `state.activePlayerId` resolves to an AI seat (and `aiReady`, and — online — `aiDriver`); reducers park `activePlayerId` on the next seat owing a simultaneous decision (Sushi Go `selecting`, 7 Wonders `picking`, Leaders `leaderDraft` / `leaderPlay`; `nextSimultaneousSeat`) and on a click-through screen in all-AI matches (Sushi Go `roundEnd`, 7 Wonders `militaryEnd`) so the driver self-advances. Starting a new match still needs the host (the rules tie `start` to the host's uid).
- **Chat**: stored in the room (`chat/`, de-duplicated by message id) so rejoiners see it; mirrored in `networkStore.chat`, not part of `GameState`. System lines (joins, leaves, match start, warnings) are made on each device. `ChatPanel` floats bottom-right in-game; the lobby shows the last lines.
- **Store wiring**: `networkStore` registers `gameStore`'s broadcast handler (→ `ActionSync.local`) and dispatch guard at creation; `gameStore` has no awareness of the network. `networkStore` reaches games only through the registry and the `GameModule` contract.
- **Tests**: `fakeTransport.ts` has the same semantics as the database (write-once start / slots, atomic lobby, async events; `up = false`, `holdWrites` / `releaseWrites` to stage races). `networkStore.test.ts` runs several "devices" (fresh store copies via `vi.resetModules`) against a stand-in registry (`store/testGames.ts`): join / not found / unreachable + retry / cancel, stale-room sweep, lobby edits and permissions, game switch, full table → spectator, chat, start, move sync, a race, rejoin, host reload (re-prepare), host hand-off (a stand-in runs the AI, hands it back), two devices racing an AI move (dropped quietly), per-seat AI levels into the match, spectating, play again, back to the lobby. `src/ui/shell.test.tsx` covers the hot-seat pass screen / whose view shows during an AI turn and the lobby's per-seat level picker; `core/seats.test.ts`, `sushi-go/hotseat.test.ts` and `seven-wonders/expansions/leaders/hotseat.test.ts` pin the simultaneous-pick order. `networkStore.games.test.ts` plays whole Machi Koro / 7 Wonders / Duel / ALS matches host + guest (+ AI) and checks every device, and a late joiner, end equal. `networkStore.live.test.ts` runs the flow, the rules and the sweep against the real project (`FIREBASE_LIVE=1`; it plants week-old rooms with the Firebase CLI and prints the rooms it used — delete them afterwards).

## AI heuristics

Every module exports a `chooseAIAction(state, playerId) → action | null`. Except for Sea Salt & Paper, Sushi Go and Jaipur (trained policies, below), all AIs are deterministic, single-difficulty heuristics — no search, no MCTS. They score the legal moves available to `playerId` and return the highest scorer. Smoke tests under `<game>/ai.test.ts` drive end-to-end AI vs AI matches to make sure no AI returns illegal actions or stalls the state machine.

Key contextual signals each AI consumes:

- **Sushi Go!** — like SSP, no hand-written AI: every difficulty is a trained policy (`aiLevels.ts`; see the Sushi Go notes). The heuristic it replaced was removed once the levels were frozen; training runs now evaluate against the shipped levels (`bench:`), their own earlier checkpoints and random.
- **Sea Salt & Paper** — no hand-written AI. Every difficulty is a trained neural-network policy (`aiLevels.ts`; see the SSP notes below). The old heuristic was removed after the shipped policies were trained; new training runs learn from scratch.
- **7 Wonders** — one-ply option scoring (`ai.ts`): every build (cheapest `planPayment`, chain, Olympia A's free build), the next wonder stage (tucking the least useful card) and a sale are valued in VP and the best is played. A card's value = the exact score delta if it stood in the city now (`scorePlayer` + expansion extras: VP, science with wilds, yellow / guild counts) + forward terms: production by Age and scarcity, trade discounts by what the neighbours sell, shields as the change in expected tokens from both neighbours at every remaining Age end (normal model, σ growing with picks left, `MILITARY_WEIGHT` 3), chains into next-Age cards, science growth; minus coins at an Age-dependent rate. Stages add their power's worth (Halicarnassus = best discard card, Babylon B / Olympia A per Age left, Olympia B ≈ best neighbour guild). Halicarnassus' `discardBuild` takes the best card. Tuned against the previous build-the-best-card heuristic, which it beats in ~80% of seat-alternated 3–7 player games (+7–9 VP per city, ~1.5 stages vs ~0.15). With expansions it also weighs the free builds (Olympia A, Caligula, a Great Project token), joining the Great Project (the expansion's `aiPickValue`: reward × the chance every token gets taken, plus the penalty avoided) and a Babel tile (`extraPickOptions`: the tower-VP step + how much the tile's rule favours it over the average rival), and the new effects (masks, rebates, coin losses, diplomacy, Architect Cabinet). Expansion-owned sub-phases go to the expansion's `chooseAIAction`: Leaders values a leader as its score delta now + what it should still earn over the picks left (draft, Recruitment — recruit / bury / discard / tile —, Solomon, the Courtesan, Rome B); Cities pays a coin loss with all it can (a coin is worth less than the debt token's VP); Babel drafts the tile that suits its city best and gives up the card it misses least to a failed project.
- **7 Wonders Duel** — one-ply (`ai.ts`): every legal action scores its own gain minus 0.7 × the best card it leaves the opponent (+ 0.7 × the best card it leaves itself after a play-again), so denial, not uncovering strong cards and supremacy threats all fall out of one term (a card that wins on the spot is worth 1000; cards a move turns face up count as an unknown average — the AI never reads a face-down card). Values are VP-equivalents: coins worth ~0.6 VP early falling to 1/3; production worth the coins it saves on the cards still to come (the pyramid's face-up cards, the age's unseen average for face-down ones, the later decks, its unbuilt wonders) at the price it would pay; shields by a blurred zone-VP curve + looting + the capital threat; a new science symbol by how close it gets to six, a pair by the best token on the board. Wonder draft from a static rank (play-again / Great Library / Piraeus first). Tuned by seat-swapped A/B; beats a random player ~99%.
- **Set** — no AI. Set is real-time with no turn order, so there is nothing for the `activePlayerId`-driven AI loop to hook into; `chooseAIAction` is deliberately absent and AI seats are filtered out at match setup. A pace-setter bot would need its own timer driver inside the game's view.
- **Machi Koro** — expected-income model (`ai.ts`): `incomeAt(state, owner, roller, total)` reads what a seat gains when a given seat rolls a given total straight off the card definitions; `roundIncome` sums it over one round of everyone's rolls (each seat on its best dice count). Rolls pick the dice count with the higher expected net; establishments score (Δ round income × `horizon`) − cost, with the cost weighed up to 2.5× as the player nears affording a landmark (so it saves); landmarks score a flat progress value + effect (immediate coins, or the edge an "everyone" landmark gives over the opponents' average), and a winning landmark is always taken. Business Center: best (gain − loss) swap; Moving Company: least valuable card; MK1 TV Station: richest opponent; MK1 Radio Tower: reroll when clearly below a fresh roll's average. With the MK1 expansions: every seat takes the Harbor's +2 when the higher total pays it more (`boosted`, inside `expectedRoll` / `roundIncome` too); a closed copy counts for nothing and the self-closing Winery for half; Demolition Company demolishes the cheapest landmark to rebuild (and is valued at +8 − that price − 3, so it isn't bought late); MK1 Moving Company gives the card it misses least to whoever it helps least; Renovation Company picks the type that collects most and closes least of its own; the Exhibit Hall is spent on a one-off payout of 4+; Tech Startup invests while (opponents × P(10) × horizon) > 1.1. `expectedRoll` doubles as the roll buttons' "avg" hint. Known weakness: it never commits to a two-dice economy from scratch (a lone 7+ card is worth ~0 while rolling one die), so MK1 bots favour cheap 1–6 cards. Tried (2026-11-05, seat-rotated MK1 base, 200–300 matches each, one new seat among old ones *and* one old seat among new ones), all reverted: valuing cards as a two-dice town always, from 3 players, or when two or more one-die rivals contest the 1–6 piles beats the current AI when it is the only one doing it (43% at 3p vs an even 33%, 33.5% at 4p vs 25%; 37.5% at 2p vs 50%) but loses once several share a table (an old seat among them wins 44–51%) — it only exploits a table of one-die bots. A dice plan chosen by looking 4–8 greedy purchases ahead (fair-share or rival-aware stock, combo pairs like Cheese Factory + Ranch, saving time at the town's real income) and a turn-order split of the two-dice niche both came out even both ways. Against itself the one-die economy holds up; a real fix probably needs opponent modelling, not a better card valuation.
- **Air, Land & Sea** — determinized one-ply search (`ai.ts`): each move is played out through the reducer in a few sampled worlds (hidden cards reshuffled, `knowledge.ts`), follow-up ability decisions answered greedily by their chooser, and scored by battle-win probability × a race-model match equity, clamped by both sides' withdraw options. See the ALS notes.
- **Jaipur** — no hand-written AI: every difficulty is a trained policy (`levels.ts` / `aiLevels.ts`; see the Jaipur notes). The heuristic it started with (once the lobby's "Classic" level and the training baseline) was removed after the levels were frozen; training runs now evaluate against the shipped levels (`bench:`), their own earlier checkpoints and random.

## Game-specific design notes (deferred implementation)

Each game's `types.ts` carries detailed notes on the eventual reducer. Short summary:

### Sushi Go! Party (`src/games/sushi-go/`)
Simultaneous pick + pass-left (every round). Engine waits at `subPhase: 'selecting'` until all players submit `submitPick` (1 card, or 2 with chopsticks on the table — the chopsticks' second card is part of the face-down pick), then reveals in one batch. Cards that need a decision once revealed, and every spoon that was on a table before the turn, queue in `state.resolution.steps` and are answered one at a time in `subPhase: 'resolving'`, with `activePlayerId` parked on the chooser: special orders first (`copyCard`), then spoons (one per player, its lowest-numbered: `askSpoon` or `keepSpoon`, then `giveSpoon` if a bare kind was asked and the giver holds several variants; skipped when every other hand is empty) / menus (`pickMenu`, 4 drawn off `state.deck` when the step comes up) / takeout boxes (`flipCards`) by the number in their corner (chopsticks 1–3, spoon 4–6, menu 7–9, takeout 10–12, stored as `variant`). A card a step puts on a table can queue more steps. End of turn: 2+ miso soups played that turn are all discarded; 10+ uramaki icons claim 8/5/2 at once (`claimUramaki`, ties share a place and skip the next; `player.uramakiPoints`, `state.uramakiNextPlace`). A special order stores `copyOf` and scores as that card (`effectiveCard`); a flipped card (`flipped: true`) scores 2 and counts as nothing else but still holds its wasabi.

Rules follow the Gamewright rulebook: hand 10/9/8/7 at 2–3/4–5/6–7/8 players; desserts join the deck 5/3/2 (2–5p) or 7/5/3 (6–8p) from a shuffled 15-card `dessertSupply`, unplayed desserts carry to the next round; maki 6/3 (6/4/2 at 6–8p), maki / temaki / pudding ties take the full points; soy sauce and tea count background colors (`colorGroup` — one per food, wasabi shares nigiri yellow). Menu builder picks 8 kinds (1 nigiri + 1 roll + 3 appetizers + 2 specials + 1 dessert); `KindInfo.minPlayers/maxPlayers` keep spoon / edamame out of 2p and menu / special order out of 7–8p (`validateMenu(menu, playerCount)`, enforced via `validateConfig(config, seats)`). **Learned-agent pipeline (`src/games/sushi-go/nn/`, trainer in `training/sgp/`)** — 2-player PPO from scratch on a random legal menu every match.
- `observation.ts` — `observe(state, viewerId)` is the only place the agent reads `SushiGoState`. Hands pass left, so the seat k places to the left holds the hand the viewer passed k turns ago, and everything done to it since is public (picks revealed, chopsticks returned openly, spoon hand-overs face-up): `knownHand` is set for offsets 1..`passes` (`passesThisRound`) and null otherwise. Hidden: unseen hands, every opponent's face-down pick, deck, dessert supply, others' menu draws / spoon-give options, RNG. Under-informs in two rare spots (own menu's returned cards, a spoon giver now holding the spoon). `nn/observation.test.ts` scrambles all of that (`testSupport.scrambleHidden`) at 2–8 players and asserts observation + features are unchanged; keep it passing when adding fields.
- `faces.ts` — 37 card faces (kind × scoring variant; corner numbers don't count).
- `encode.ts` — encoder v1, 654 floats (~100 non-zero). Seats by role, not one slot per seat, so a 2-player-trained net reads the same features at 3–8: `me`, `left` (gets my hand: their known hand + what each face is worth to them), `right` (passes me my next hand), `opps` (pooled rank races, edamame / soy competition, score margins, all known hands), `unseen` (round pool minus everything seen; pinned to equal deck + unseen hands), `decision` (type + the cards it's between). Marginals = exact Δ(round + projected dessert score) per menu face via `scoring.roundProbe`. ~150–220 µs per encode at 2p.
- `actions.ts` — action space v1, 45 slots: 37 face slots whose meaning follows the decision (play / chopsticks' second card / copy / menu pick / spoon hand-over / flip / ask for exactly this face), 5 `askAny:<kind>` (spoon asks naming no variant), `done`, `spoon:yes|no`. Multi-part answers are one decision per part, carrying a `SushiGoDraft` (`observe(state, id, {{ draft }})`, `decision.stage` / `chosen`): pick = first card → chopsticks second or `done`; spoon (at the reveal) = `spoon:yes` → the card to name, or `spoon:no` (keep it); takeout = one flip at a time until `done`. The encoder's `spoon:use` decision sits where v1's pick-time spoon call was — the shipped levels trained at 2 players, where the spoon is never on the menu, so the move to the reveal changed no weights or layout. `actions.test.ts` walks every legal slot sequence against the reducer.
- `agent.ts` / `policy.ts` — `actWithPolicy` (runs the parts), `loadSushiGoPolicy` (game `sushi-go`, refuses other encoder / action-space versions), greedy / sampled play.
- Training: `training/sgp/` mirrors `training/ssp/` (agents `random` / `nn:` / `nn-sample:`, `sim.ts`, `vec-env.ts` — simultaneous picks asked seat by seat, `env-server.ts`, seat-swapped `evaluate.ts`/`eval.ts`, Python `env_client.py` / `evaluate.py` / `train.py`, reusing `training/ssp/model.py` with `game='sushi-go'`). Its bundle builds to `training/sgp/dist/` (`npm run sgp:build`), apart from SSP's `training/dist/`, so an SSP rebuild can't pull it out from under a running trainer. Runs land in `training/runs/sgp/<run>/`; progress.md columns are vs each shipped level (`--eval-bench`, hardest first) / vs 500 updates earlier / vs random.

Timing: the chopsticks' second card is chosen with the face-down pick; spoons are used (or kept) and special orders pick their copy at the reveal.

### Sea Salt & Paper (`src/games/sea-salt-paper/`)
Each turn: draw 2 (keep 1 or both), optional play-pair-for-ability, then STOP / LAST CHANCE / pass. "LAST CHANCE" triggers a peer-relative final round — proposer wins bonus only if their score still leads. Multi-round; first to `targetScore` ends the match. Base families: mermaid, shark/swimmer/crab/boat/fish (duos), shell/octopus/penguin/sailor (collectors), lighthouse/shoal/penguinColony/captain (multipliers).

**Expansions** (togglable per match via `config.expansions`):
- *Extra Salt* — adds jellyfish/lobster/starfish/seahorse/crabBasket to the deck (8 cards). New duo pairings (jellyfish+swimmer, lobster+crab) handled in `isValidDuoPair`/`duoPartner`. Starfish trios are a new action type `playTrio` and stored as `player.trios` so scoring can flatly award 3 pts and skip the duo ability. The trio replaces the duo's 1 pt (net +2) but its cards still count as boats / fish / crabs for the lighthouse, shoal and crab basket (`scoring.ts` pairs from `trioCancelledIds`-filtered counts, multipliers from all cards). Lobster reveal lives in `subPhase: 'awaitingLobsterPick'` with `pendingLobsterPick` buffer. Jellyfish + swimmer locks every opponent (`state.lockedPlayerIds`): a locked player's next turn can only be "take the top card of the deck" — no discard pile, no pairs, no STOP / LAST CHANCE — so `startTurn` in the reducer plays it for them (`jellyfishDraw` log entry, family private like a fish draw, then a normal `pass` via `endTurn`) and moves on, so no decision is ever made while locked (bar an Angelfish pick as that turn ends). An empty deck at that moment ends the round; a forced fourth mermaid still wins.
- *Extra Pepper* — separate event deck (`state.event`), rules from the official rule sheet (summarised in `events.ts`'s header). One event revealed per round (`startNewRound`); its rule applies to everyone that round via `eventAppliesTo`. At round end `settleEvents` (after scoring): a held card whose holder is no longer alone in first (`+`) / last (`−`) place is discarded, then the round's card goes to the sole leader (`+`, the four handicaps: Kraken, Tornado, Treasure Chest, Diodon Fish) or sole laggard (`−`, the eight boosts) — discarded on a tie (`eventDiscarded` log, reason `tie` / `lostPlace` / `choice`). A winner already holding a card picks which to keep: `subPhase: 'awaitingEventChoice'` (`pendingEventChoice`, `activePlayerId` parked on the chooser, `chooseEvent`). Skipped once the match is decided. Interactive events: The Hermit Crab digs through each pile (`crabPilesLeft`, two `crabPick`s); The Angelfish asks which same-colour top to take (`awaitingAngelfishPick`, `pendingAngelfish.via`) on a pass or LAST CHANCE, not STOP; The Water Rodeo makes two swimmers / two sharks duos (`isValidDuoPair(…, { waterRodeo })`, scored too) — swimmers: `awaitingRodeoTarget` → `rodeoLook` → `awaitingRodeoSwap` → `rodeoSwap` (or null), sharks: `awaitingPairSteal` → `stealPair` (pairs read back off the table by `tablePairs`); The Coral Reef: `placeCoralShell` puts a shell face down (`player.coralShell`, scores nothing) and `canAttack` then shields that player from shark steals, the Water Rodeo and the jellyfish lock. The Tornado zeroes mermaid points only (the LAST CHANCE colour bonus stays). Any card entering a hand checks the mermaid win (`endIfMermaidWin`). `events.test.ts` covers every rule; `ui.test.tsx` every new prompt.

**Hidden-information rules** (`src/games/sea-salt-paper/knowledge.ts`, under the learned agent's observation — the single source of truth for what a seat may know). `knowledgeOf(state, seatId, { lookingAt })` replays this round's log:
- *Opponents' hands*: known only via cards taken off a pile's visible top (discard draws, crab picks of the top card, Angelfish) and cards they stole from this seat — tracked by card id until played to a table or stolen back. Deck keeps, fish draws, lobster picks, crab digs below the top, and steals between two other players are hidden.
- *Discard piles*: remembered in full (every card landed face-up) until an opponent's crab digs out a buried card. The seat then knows the pile is a card short (`unknownRemovals`) but not which one, until that card shows up on a table, the seat steals it, or the seat digs through that pile itself (and learns what's gone — and so what the digger holds).
- Log entries carry the exact `card` moved, `fromTop` on crab picks, `auto` on Hermit Crab picks. Reading `entry.card` is only legitimate where the rules above say the seat saw it.

**Card animation** (`cardFlip.tsx`): one FLIP harness flies every card move. Each card registers its node + zone (`useFlipCard`), the deck and each pile a card-sized anchor (`useFlipAnchor`); `SspFlipProvider` (a class, for `getSnapshotBeforeUpdate`) reads every card's on-screen rect before React mutates the DOM, then animates cards whose zone changed from there — or, for a card not shown before, from the anchor of where the previous state kept it (`cardOrigins` in ui.tsx: deck / unseen draw / lobster reveal → deck, buried → its pile). Web Animations API, so interrupted flights restart mid-air and hover / selected transforms are untouched. Piles render the card under the top too, so a landing card covers it. A `scene` change (new round, summary, game over) animates nothing. `cardFlip.test.tsx` pins the rules with fake rects.

**AI difficulty levels** (`levels.ts` lists them, `aiLevels.ts` loads and plays them; each AI seat has its own, `seat.aiLevel`, default `normal`, picked on its seat row in the lobby): easy / normal / hard = `policies/easy-update100.json` / `normal-update1000.json` / `hard-pepper-update17500.json`. Easy and normal are updates 100 / 1000 of `training/runs/ssp/main` (2-player Extra Salt). Hard is `training/runs/ssp/pepper` update 17500, the end of three runs: main's update 10000 (`hard-update10000.json`) → 4,000 updates on 2, 3 and 4-player Extra Salt (`runs/ssp/multi`: `--players 2,3,4 --init …update_010000.pt`, then `2,2,3,4` from update 11749 when 2p began to slip → `hard-multi-update14000.json`) → upgraded to v3 + taught, then 3,500 updates on 2–4 players with and without Extra Pepper (`runs/ssp/pepper`, see "Where to start next"). Both earlier Hards stay in the folder as eval benchmarks but are no longer imported, so not shipped. Head to head over 2000 seat-swapped 2-player Extra Salt matches: normal beats easy 61%, hard beats easy 76%, normal 67%, the multi hard 55.6% and the 2-player hard 55.5%; all beat random ~100%. Against the multi hard on fresh deals (3000 matches per table) it wins 53.5% at 2p, 35.6% at 3p (even 33.3%) and 28.6% at 4p (even 25%); with Pepper 57.9% / 39.1% / 31.2%; 53.4% in the 2-player base game (2000). (The multi hard had beaten the 2-player one 51.0% at 2p, 44.5% at 3p and 37.4% at 4p at tables of its copies.) Updates 100 and 1000 predate white counting for mermaid claims. Every level loads the same way: Vite emits each ~1.7 MB JSON (~1.2 MB gzipped) as a hashed asset (`?url` import, never in a JS chunk), `module.prepare` dynamic-imports `aiLevels` (keeping the network code out of the picker bundle) and fetches every level the AI seats use, once per page; the lobby starts those fetches as soon as the levels are picked. Only Hard trained with Pepper (easy and normal play its decisions with the taught fixed rules); every level plays 2–4 players and any expansions legally (`aiLevels.test.ts` plays full 2/3/4-player matches on every level). The policy files are also the eval tools' benchmarks (`bench:hard-update10000` etc.; `bench:normal-update1000` is the "1k" reference). **Any ENCODER_VERSION / ACTION_SPACE_VERSION bump makes the shipped files fail to load (the test catches it) — retrain and re-freeze them, or, if the bump only appends inputs / slots, upgrade them the way `upgrade.py` + `teach.py` did for v2 → v3.**

**Learned-agent pipeline** (`src/games/sea-salt-paper/nn/`, 2-player base + Extra Salt; Pepper is legal but untested strategically):
- `observation.ts` — `observe(state, viewerId, { crabLookPile })` is the **only** place the agent pipeline reads `SspState`. It returns a seat-relative `SspObservation` built on `knowledgeOf`: own hand, every table, pile views (top, size, remembered buried cards, `unknownRemovals`), deck size, hand sizes, scores, events, own pending draw / lobster reveal, `knownCards` per opponent (and, for the viewer, what the opponents know about its hand). `observation.test.ts` scrambles everything hidden (incl. which card an unseen crab dig took) and asserts observation / features / mask are unchanged. Keep that test passing when adding fields.
- `actions.ts` — action space v3, 141 slots (decisions, not physical cards: "play a crab pair", "keep card 0 and discard to pile 1"), `legalMask(obs)`, `decodeSlot(obs, slot)`, inverse `slotForAction`. The first 66 are v2's, unchanged; the Extra Pepper ones follow (Water Rodeo duos + trios, `coral:place`, `rodeoLook:+k`, `rodeoTake:<family>` / `rodeoSwap:none` / `rodeoGive:<family>`, `pairSteal:+k:<pair type>` over `PAIR_TYPES`, `angelfish:<pile>`, `event:keepNew|keepOld`). Two decisions take two steps: a crab pick (`crabPile:N` → a `CrabLook`, then — re-observing with `crabLookPile`, which reveals that pile — `crab:<family>`) and a Water Rodeo swap (`rodeoTake:<family>` → a `RodeoTake`, then with `rodeoTake` set `rodeoGive:<family>`). `nextStep` (agent.ts) turns a first step into the next observation's options; `actWithPolicy` and the vec env drive both. `actions.test.ts` is a two-way oracle against the reducer (everything the reducer accepts is masked in; everything masked in decodes to something the reducer accepts).
- `encode.ts` — encoder v3, 833 floats from the observation only (counts, remembered pile contents, unseen pool, known opponent cards, per-family score deltas). The first 632 are v2's, unchanged; the Extra Pepper segments follow: `pepper.*` (events still to come, Coral Reef shells, 3-mermaid wins, shell placeable, Water Rodeo pairs in hand — all zero without Pepper) and `pepperDecision.*` (only written in the Pepper decision subphases, where only Pepper slots are legal: the look target's lead / hand / leader flag, the hand looked at with each kind's gain, the kind chosen to take and each give's cost, opponents' table pairs by type with their gain, the two event cards). Layout comes from the writer itself (`featureLayout()`), so it can't drift; `encode.test.ts` pins the v2 prefix and both zero rules.
- `ENCODER_VERSION` / `ACTION_SPACE_VERSION` are pinned in tests next to `OBS_DIM` / `NUM_SLOTS`. Bump on any layout change; trained weights must carry both and be refused on mismatch.
- `agent.ts` — `actWithPolicy(state, pid, (obs, mask) → slot)` adapts any slot policy to the `chooseAIAction` shape (and runs the two-step decisions). The network makes every decision — nothing is answered outside it at runtime.
- `fixedChoices.ts` — hand-written answers to the Extra Pepper decisions (event keep-or-swap, Angelfish pick, playing Water Rodeo duos, the look target / swap / pair steal, Coral Reef shell), from the observation, by score. Not played at runtime: it is the teacher `training/ssp/teach.py` copies into the Pepper slots of a policy upgraded from v2, and the bar a Pepper-trained policy should beat.
- **v2 → v3 upgrade.** v3 only appended inputs and slots, so `training/ssp/upgrade.py` turns a v2 policy (or checkpoint) into a v3 one by padding — zero weights on the new inputs, new zero output rows: every v2 decision plays exactly as before (checked match for match on 2/3/4-player and base-game evals). `teach.py` then fits the Pepper slots to `fixedChoices.ts` on decisions from Pepper matches the policy plays itself (`teach-data.ts`), training only the Pepper output rows and the first layer's `pepperDecision.*` columns, so no v2 decision can change (the tool checks every other weight is untouched). The shipped files are all upgraded + taught (`meta.upgradedFrom`, `meta.taught` with the held-out agreement per decision kind).
- `policy.ts` — `loadSspPolicy(file)` validates a trained policy file (game, `encoderVersion`, `actionSpaceVersion`, dims) and refuses mismatches; `greedyPolicy` / `sampledPolicy` turn it into a slot policy.
- `src/ai/mlp.ts` sums each layer over its non-zero inputs only (bit-identical to the dense sum). ~80 of the 833 features are non-zero, so a forward pass of the shipped policies takes ~70 µs instead of ~225 µs.
- Training lives in `training/ssp/` (`train.py`: PPO from scratch, self-play + past-checkpoint opponents; `evaluate.py` for match / baselines / ladder + Elo / analyze). See `training/README.md`.

### Air, Land & Sea (`src/games/air-land-sea/`)
Strict 2-player. Rules and card text are the **Revised Edition** rulebook + cards and **Spies, Lies & Supplies** (SLS: its cards, key terms, the Epic Supreme Commander column and the official Epic update) — read from page images of the rulebooks and printed cards, since the publisher PDFs were unreachable; the `cards.ts` text is what the cards say. A battle's deck is the six cards (strengths 1–6) of each theater in play — any 3 of the 6 (base Air / Land / Sea, SLS Intelligence / Diplomacy / Economics), or 5 in Epic Mode; 6 cards each (10 in Epic), the rest stay as the face-down deck (top = last element, destroyed cards go to index 0). Theater row and 1st player come from the seed (`config.randomOrder`, default true). Each turn: **Deploy** (face up to the matching theater; its ability fires), **Improvise** (face down anywhere: strength 2, no ability) or **Withdraw**. A battle ends on a withdrawal or once both hands are empty (a player with no cards while the other still has some passes); the player controlling more theaters wins (1st player wins ties and empty theaters; 3 of 5 in Epic). Full battle 6 VP; a withdrawal scores the withdrawer's Supreme Commander chart (`WITHDRAW_CHARTS`: 1st 4+/2–3/1/0 → 2/3/4/6, 2nd 5+/3–4/2/0–1; Epic 1st 6+/3–5/1–2/0, 2nd 7+/4–6/2–3/0–1). Beginner Mode (`config.beginner`): 1 VP per battle. Between battles the rightmost theater moves to the left end and the commanders swap. The 3 in every theater is the same flip (Maneuver / Manipulate); the 6 has no ability.

**Ability engine** (`abilities.ts`): an Instant goes on `state.queue` when its card is played face up or flipped face up, and the queue resolves first in, first out, each ability fully before the next (Revised Edition rule — *not* the 2019 clarification that let a triggered ability interrupt Disrupt). The resolving one is `state.frame`, a small step machine per ability (`IMPLS`) that either finishes or asks a player: `state.pending` (`prompt`, legal `cards` / `theaters`, `optional`, `drawnCardId` / `revealedCardId`), `subPhase: 'resolving'`, `activePlayerId` = the chooser — so the host AI driver and the hot-seat pass screen follow decisions that belong to the opponent (Disrupt's second flip, Surveil's reveal, Arms Race's second theater). Every answer is one `{ type: 'answer', answer: AlsAnswer }` action, validated against `pending`; `reducer.drain` then keeps resolving until someone must decide or the turn ends. A queued ability whose card was flipped down / destroyed / returned before it began never starts; one that began always finishes. `performPlay` is the only way a card enters a theater from a hand (main action, Redeploy's "play a card", Reinforce's forced face-down play): deploy permission (`rules.deployVia`: match → Air Drop → Aerodrome → Supply Lines, which gives the enemy 1 supply), Neutralize obligations (`player.neutralized`: only those cards, face down), Air Drop consumed by any play, then Containment / Blockade destroy the card before it can act, then the played card's instant and any adjacent Envoy trigger are queued. Ongoing abilities are read off the board in `rules.ts` (strength: Cover Fire, Escalation, Support, Spy Network, supplies) — only Envoy is queued. In Epic Mode ongoing abilities reach only their own and the adjacent theaters (`inRange`). Destroyed = face down to the deck bottom. Higher / lower compares printed strength in hand and the value showing in play (face down = 2, `shownValue`); Retrofit gains the card's current strength. Incite re-runs a copied instant as a fresh frame on Incite's own theater and owner (`viaIncite`). Readings where printings differ: Incite copies an *instant* ability and Surveil flips an uncovered *face-up* card (the ALS-branded SLS text as owners quote it; the Critters at War reprint words both more loosely).

**Hidden information**: hands, face-down cards, the deck. `player.known` = hand cards the opponent has seen (revealed by Leverage / Requisition / Surveil / Neutralize, or given by Give & Take) until they leave the hand. Log entries for an improvised / forced / drawn / returned card carry `private: seat`; `Sidebar.tsx` names those cards to their owner only (and to spectators). `knowledge.ts` — `unseenCards(state, viewer)` and `determinize` (unseen cards shuffled among the unseen places, returning the id mapping) — is the AI's only view. `moves.ts` enumerates every legal action / answer (AI, fuzz test).

**UI** (`ui.tsx`): the turn player picks a hand card (Deploy / Improvise toggle), then a highlighted theater; withdraw is a two-step confirm showing the VP it concedes. A decision panel (`Decision`) carries every prompt: highlighted board cards (flip / destroy / retrofit / incite / transport's card then theater), highlighted theaters (Reinforce, Arms Race), hand cards (reveals), buttons (Give & Take, Envoy, skips) and a name picker for Neutralize that dims cards you can see aren't in the enemy's hand; the other player sees who is deciding what. The opponent's revealed cards show face up in their hand row; your hand marks Revealed / Drawn / face-down-next cards. Epic Mode's five narrow columns put the strength badge on the centre line (`.als-board.epic`). The sidebar is the history (online chat is the shell's panel).

**Art** (`art.tsx`, flat SVG, no `<defs>`): one illustration for each of the 36 cards (`SCENES[theater][strength - 1]`), theater emblems (Economics a `$`) and banners in the printed colours (Air gray, Land green, Sea blue, Intelligence charcoal, Diplomacy purple, Economics brick — `THEATER_TINT`), Instant / Ongoing markers, card back, VP medal, control flag, supply token. `Card.tsx` draws hand cards (with an optional corner badge), board cards (header strip + `→N` chip when modified), peeks at your own face-down cards, opponents' backs, and `MiniFace` (revealed hand cards).

**AI** (`ai.ts`): one-ply search over 6 determinized worlds (3 when there are 40+ moves): every candidate is played through the real reducer, follow-up decisions resolve greedily by their own chooser, and the result is scored — battle-win probability (per-theater margins plus the expected strength of both hands, logistic per theater, combined into "holds a majority") weighs winning and losing, clamped between withdrawing next turn and the opponent conceding, all valued as the change in a race-model match equity (`needOpp^1.5 / (needMe^1.5 + needOpp^1.5)`), plus small terms for Air Drop, Neutralize obligations, revealed cards and Aerodrome / Supply Lines / Envoy. Withdrawal is scored exactly. Beats random play every game (`ai.test.ts`); constants were picked in seat-swapped self-play (the variants tried landed within ±4% of each other). ~1–5 ms a decision.

Tests: `rules.test.ts` (deck, strength, control, charts, Epic range), `reducer.test.ts` (flow + every base ability, queue order), `sls.test.ts` (every SLS ability, Epic), `moves.test.ts` (random play through six modes with card conservation), `ai.test.ts`, `ui.test.tsx` (hidden info from both seats, every decision prompt, lobby, all 36 faces). `testSupport.ts` arranges exact positions.

Not modelled: the SLS 3–4 player team variant (the module is strictly 2-player).

### Jaipur (`src/games/jaipur/`)
Strict 2-player trading game, first to `JaipurConfig.sealsToWin` Seals of Excellence (1–3; default 2 = best of three). Rules summary in the `types.ts` header, card / token tables in `cards.ts`. A turn is exactly one of `takeOne` (one good; the deck refills that slot), `takeCamels` (every market camel, into `player.herd`), `exchange` (2+ goods for as many hand cards and/or herd camels — never a good of a type being taken) or `sell` (one good; diamond / gold / silver ≥ 2; tokens off the top of its pile, plus a shuffled ×3 / ×4 / ×5 bonus token for 3 / 4 / 5+ cards). Hand limit 7; camels never sit in the hand. The round ends the moment the third goods pile empties, or a refill needs a card the deck no longer has (a deck emptied exactly plays on). Camel token (5) to the strictly bigger herd; the seal goes to the most rupees, ties → more bonus tokens → more goods tokens → no seal, play another round. The loser starts the next round; round one's starter is drawn from the seed. All randomness (deck order, bonus piles, starter) is drawn in `setupRound`, so actions carry no payload. A replacement card takes the market slot of the card it replaces (the market doesn't reshuffle on screen).

- `rules.ts` — legality on card counts, shared by reducer, AI, UI and the NN mask. `legalMoves(ctx)` lists every distinct move; `canCompleteTrade` / `canTakeMore` / `canGive` answer "can this half-built exchange still be finished?" in closed form (a take set of t goods is payable iff the hand goods of untaken types ≥ max(0, t − camels, hand + t − 7); growing the take set never makes it payable again, so a card-by-card builder never dead-ends). `rules.test.ts` checks both against brute force.
- `knowledge.ts` — what a seat knows, by card type: everything public (market, discard pile, herds, goods tokens, bonus counts per size) plus the opponent's goods taken from the market this round and not yet given back or sold (playing a type they're known to hold drops the known count; otherwise the unknown part shrinks — either way nothing is lost, cards of a type being interchangeable). Unseen = deck + the opponent's unknown cards. An opponent's bonus values are hidden; the `bonus.value` on their sale log entries is private and must not be shown or read. The UI never shows these: as at the table, remembering what the opponent took is the player's job (the AI remembers perfectly).
- **UI** (`ui.tsx`): turns are built by selection — market goods, hand cards and herd camels — and `intentOf` names the move it adds up to (take one / take all camels / trade N for N / sell N) or says what's missing; quick buttons for "take camels" and "sell all of a good". The opponent's hand is drawn face down and their bonus tokens value-less until the round is scored; with no seated viewer and all-AI seats both hands are shown. Hot-seat flips the point of view each turn (GameHost's pass screen covers it); the sidebar log says what just happened (online chat is the shell's floating panel, as in every game). `art.tsx` — flat hand-drawn SVG (seven card faces in a Mughal-arch frame, card back, goods / bonus / camel tokens, seal), no `<defs>`. The rule book is `RuleBook.tsx` — not `Rules.tsx`, which would collide with `rules.ts` on case-insensitive file systems.
- **Animations** (`flip.tsx`, FLIP like SSP's but scale-aware and keyed by string: `c<id>` cards, `t<id>` goods tokens, `b<id>` bonus tokens): an item changing zone flies from its old rect and size (a small face-down opponent card grows into a market card); a card first seen comes off the `deck` anchor and turns face up mid-flight; items landing in one zone together stagger 70 ms apart (a sale's tokens peel off the price board one by one). With a human at the table an AI's move flies at `pace: 'slow'` (760 ms, 130 ms stagger) and the module's `aiDelayMs` is 1 s, so the human's own move lands before the AI answers; every sold card is rendered in the discard pile so they all fly there. Fresh market cards glow; selected cards lift. `scene` = round + point of view, so a new round or a hot-seat hand-over animates nothing; the round summary / game-over panels sit over the board and fade in after ~1 s so the round's last move still lands, then the seal pops. Reduced motion turns it all off. `flip.test.tsx` pins the rules with fake rects; `ui.test.tsx` clicks through every move type.
- **Match stats** (game-over overlay; `stats.ts` → `StatsPanel.tsx`, derived from the log + `roundHistory`, nothing extra recorded): each round as a race — rupees, herd or hand size after every move, each move named in the tooltip (the opening herd isn't logged, so it's worked back from the round's final herd; the opening hand is the rest of the five dealt) — round scores by source (goods / bonus / camel token), rupees per good, sale sizes, the move mix and key numbers. Shown only at game over, when every bonus value is public. The final overlay grows past the board (`.jp-final`).
- **Learned-agent pipeline** (`nn/`, trainer in `training/jaipur/`). `observation.ts` — `observe(state, viewerId, { draft })` is the only place the agent reads `JaipurState`: own hand / herd / tokens with bonus values, the opponent's known cards / unknown count / herd / goods tokens / bonus counts, what the opponent knows of the viewer's hand (`exposed`), unseen card and bonus pools, and the decision (`main`, or an exchange draft's `take` / `give` stage). `observation.test.ts` scrambles the deck, the opponent's unknown cards, the bonus piles with their bonus values and the RNG and asserts observation, features and mask are unchanged. `actions.ts` — action space v1, 63 slots by card type (`take:<good>`, `camels`, `sell:<good>:<n>` n=1..7, `trade:<good>`, `trade:done`, `give:<type>`); an exchange is asked one card at a time with a `JaipurDraft` (take goods → `trade:done` → give cards; submitted once as many are given as taken). `actions.test.ts` walks every legal slot sequence and requires it to reach exactly `legalMoves`, every one accepted by the reducer. `encode.ts` — encoder v2, 310 floats: match (round, seals, starter), clock (deck size, empty piles), hands (own counts; opponent hand size, known cards, unknown count; what the opponent knows of ours), camels (herds, race, market, deck — exact, camels never stay in a hand), cards per good (market, unsold, unseen = deck + opponent's unknown), the deck's expected make-up and next-card odds (unseen goods split pro rata between deck and the opponent's unknown cards), every pile's full remaining price ladder, what selling 1..7 of each good pays now, bonus piles (left, and the unseen values per value — the printed piles minus the viewer's own tokens), rupee margins (opponent's bonus at the unseen mean) and tiebreak leads, the exchange draft. `encode.test.ts` checks the ladders, unsold counts, expected deck and unseen bonus values against the state. `agent.ts` / `policy.ts` — `actWithPolicy`, `loadJaipurPolicy` (game `jaipur`, refuses other versions), greedy / sampled play. **AI levels** (`levels.ts`, `aiLevels.ts`; each AI seat has its own, `seat.aiLevel`, picked on its seat row in the lobby): `levels.ts` globs `./policies/*.json` at build time (`import.meta.glob`, `?url` — each file a hashed asset), and a file named `easy-…` / `normal-…` / `hard-…` becomes that level; the lobby offers exactly those on every AI seat (`module.aiLevels`), defaulting to the strongest. So `evaluate.py freeze RUN@N --name hard-update8000` is all it takes to ship a level. `module.prepare` dynamic-imports `aiLevels.ts`, which fetches every level the AI seats use, once per page (the lobby starts the fetches when the levels are picked); until then `chooseAIAction` answers null, and in all-AI matches it clicks through the round summary. `aiLevels.test.ts` loads every shipped file and plays matches with it. **Any ENCODER_VERSION / ACTION_SPACE_VERSION bump makes shipped files fail to load — retrain and re-freeze.**

### Machi Koro (`src/games/machi-koro/`)
One module, two editions (`MkConfig.edition`, default `mk2`); the edition differences are data in `cards.ts`'s `EDITIONS` (start coins / city, opening build rounds, `market: 'rows' | 'open' | 'marketplace' | 'hybrid'`, `landmarks: 'market' | 'personal'`, landmarks to win, broke coin, two dice for all, one purple each, purple swaps), so the reducer has no edition switches. **MK2** (2–5p): 5 coins, no cards, 3 build-only opening rounds (`subPhase: 'setupBuild'`, establishments only), a 5-5-5 market — rows `low` (1–6), `high` (7+), `landmark` — dealt from shuffled decks until each shows 5 different stacks (a drawn duplicate stacks on its twin; a sold-out stack's gap is refilled in place; empty decks just shrink the row). Landmark price = `costs[landmarks already built]` (12/16/22, 10/14/22, Launch Pad 45/38/25), Loan Office −2 (owner) and Observatory −5 off the Launch Pad (everyone). Win on the 3rd landmark or the Launch Pad. **MK1** base (2–4p): 3 coins + Wheat Field + Bakery, every pile face-up (rows with empty decks; sold-out piles stay at 0), the four personal landmarks (Train Station 4 / Shopping Mall 10 / Amusement Park 16 / Radio Tower 22, all owner-only), win with all four; one of each purple per player in the supply.

**MK1 expansions** (`MkConfig.expansions`: `harbor`, `millionairesRow`; `MkConfig.supply`: `open` | `marketplace` | `hybrid`, absent = the marketplace once an expansion is in). The cards live in `cards.ts`'s `EXPANSIONS` (tagged `expansion`; MK1's indexes hold them all, ids never clash) and `rulesFor(config)` merges base + expansions into one memoised `MkEditionRules` (`rulesOf(state)` everywhere) — max players, landmarks (sorted by price; `landmarksToWin` = all of them), `startLandmarks`, supply. *Harbor* (2–5p): City Hall (`prebuilt`, broke coin before building), Harbor (2; `addToRoll` → `subPhase: 'harbor'`, add 2 to a final roll of 10+, so 13–14 exist; `roll.added`), Airport (30, +10 on a pass); 10 establishments — Sushi Bar (cost 4 as printed outside Japan; the Japanese card costs 2) / Mackerel Boat / Tuna Boat need the Harbor (`condition: ownerHas`), Tuna Boat's `bankRoll` rolls 2 dice once per turn (`turn.bonusRoll`, `bonusRoll` log) and every copy earns the total, Flower Shop counts Flower Orchards (`bankPerCard`), Publisher (cup + shop per opponent), Tax Office (half from 10+). *Marketplace*: every establishment in one shuffled deck, row `mixed`, dealt until 10 different piles show (`rowSize`). *5-5-2 market* (`hybrid`, the "hybrid supply" variant): three decks — establishments activating on ≤6 (`low`), on 7+ (`high`), majors (`major`, `MAJOR_ROW_SIZE` 2) — each dealt until 5 / 5 / 2 different piles show; a sold-out pile is refilled from its own deck. *Millionaire's Row*: 14 establishments — `condition` on landmarks built (`landmarksBuilt` never counts a prebuilt City Hall), renovation (`player.closed[cardId]` copies; a closed copy reopens instead of activating — `reopened` / `closed` logs; Winery `closesAfter`; Renovation Company → `subPhase: 'renovate'`, closes every copy of a non-major type, 1 per opponent copy), Demolition Company (`subPhase: 'demolish'`, +8, the landmark comes off and can be rebuilt), Loan Office (cost −5, `payBank` 2), MK1 Moving Company (`subPhase: 'give'`, any opponent, +4 — not MK2's `gift`), Soda Bottling Plant (everyone's cups), Tech Startup (`player.invested`; `invest: true` on the `build` / `pass` action puts 1 coin on it as the turn ends; pays the investment from each opponent), International Exhibit Hall (`subPhase: 'exhibit'`, activate one of your open blue / green cards instead, then the Hall returns to the market), Park (redistribute). A moved card keeps its closed state: the giver hands over a closed copy first, a Business Center taker gets an open one. `expansions.test.ts` covers each card; `ai.test.ts` plays AI-only and random matches with both expansions.

Turn: `roll` (1 or 2 dice, drawn from `state.rngState`) → [`reroll` — MK1 Radio Tower keep / reroll once] → `resolveRoll`: red (opponents', counter-clockwise from the roller, each paid in full before the next; a short payer pays what they have and the rest is lost) → blue (everyone) + green (roller) from the bank → purple (roller, copy by copy) → ongoing landmarks (Tech Startup, Renovation Company, Temple, then City Hall / Charterhouse if `turn.received` is still 0, then Amusement Park, Moving Company) → queued choices `demolish`, `give` (MK1 Moving Company), `tvTarget` (MK1), `renovate`, `exhibit`, `exchange` (Business Center, one per copy, optional, skipped when no swap is possible), `gift` (MK2 Moving Company, to the player on the roller's right) — each skipped when impossible → broke coin (MK2 rule, or MK1's City Hall) → `build` (one card or pass; Airport +5 / +10 on a pass; Tech Startup investment). The Harbor's `harbor` step sits between the final roll (after any Radio Tower reroll) and `resolveRoll`. Ongoing landmarks are read where they apply via `landmarksInForce(state, playerId)` (`scope: 'everyone'` once anyone built it, `'owner'` for its builder); immediate ones fire in `applyImmediate`. Amusement Park + Radio Tower in one turn = one extra turn. Combo cards carry symbol `'none'` so they never count themselves. Card data was cross-checked between two independent MK2 engines (one written against the rulebook PDF); copy counts follow the rulebook-checked one (Stadium 4, Hamburger Stand 4 — the other has 3 / 5; both total 86).

Everything is public, so the module sets `hiddenInfo: false`. UI: `Card.tsx` (faces — colour band + activation pill, name, art, effect line, cost coin, symbol; landmarks show their price ladder with the viewer's price highlighted and a scope badge; `face` is the card-face wording, `text` the full rule), `art.tsx` (54 hand-drawn flat SVG scenes, no `<defs>`/ids, plus symbol badges; expansion cards that show an existing building reuse its scene), `fx.tsx` (animation layer — see below), `ui.tsx`, `Sidebar.tsx` (history feed), `rules.tsx` (11-page rulebook incl. card tables, rulings, dice odds, MK1 differences, Harbor, Millionaire's Row). `ui.tsx` lays the game out like the Catan project's game view: the market is the board (bank + dice tray in its header), the bottom strip (sticky) holds your own town next to the action panel (phase, prompt, buttons; with no seat of your own it shows the active player's town), and the 300px side column holds the history and every opponent's town as a compact card (`xs` card faces; Business Center picks still work there). The lobby has the edition picker, the MK2 promo toggle, and MK1's expansion checkboxes + supply choice.

**Animations (`fx.tsx`)**: elements register named anchors (`bank`, `coins:<pid>`, `market:<cardId>`, `city:<pid>:<cardId>`, `lm:<pid>:<lmId>`); after every commit `FxProvider` snapshots their page rects, and new log entries animate between the previous snapshot (where a card was — the market slot it left) and the live DOM: coin sprites arc payer/bank → payee with ±N floats and a pulse on the card that paid, card ghosts fly market → town (a brand-new town stack stays hidden until its ghost lands) or town → town (exchange / gift), toasts for landmarks, extra turns and wins. Coin flights wait `DICE_MS` when the batch holds a roll. Web Animations API only (never fights React over classes), portal on `<body>`; skipped under reduced motion, without `Element.animate` (jsdom) and for log jumps ≥ 80 entries (snapshot on join). The dice tray tumbles on each new roll's `seq`.

## Conventions

- Strict TypeScript. No `any` unless genuinely necessary.
- Co-locate tests next to code: `reducer.ts` and `reducer.test.ts` side by side.
- The game logic in `src/games/<id>/` must not import from `src/ui`, `src/net`, or `src/store`.
- The net layer may import from `src/core` but not `src/ui`.
- Path alias: `@/` → `src/`.
- Game-specific UI is lazy-loaded via `module.ui()` — keeps the picker bundle tiny.
- Don't introduce game-agnostic code into a game folder. Don't introduce game-specific code into the shell. If you're about to, you probably want a new field on `GameModule` or `GameStateShape` instead.

### 7 Wonders implementation notes

- Cards: `src/games/seven-wonders/cards.ts` — templates for Ages I/II/III + Age III guilds; each `appearances` entry is one physical copy at its printed player count ("3+", "4+"…), so every Age is exactly `playerCount × 7` (checked against the rulebook list; `rules.test.ts` pins sizes and copy counts; 8 players use the 7-player deck). Card ids are positional — Age × 1000 + position, guilds 3300+, expansion guilds 3400+ / 3450+, black cards Age × 1000 + 500 +, leaders 10000+ — so building a deck anywhere (a rule book, a test) never shifts the ids a match deals (a module-level counter used to, which would have desynced online devices).
- Wonders: `wonders.ts` — all 7 wonders × A/B sides, first-edition costs, plus the expansion boards (`expansion` tag, dealt only with it: `availableWonders`): Petra and Byzantium (Cities), Rome (Leaders; its power is a board effect, `boardEffects`, in force from the start — `wonderEffects` = board + built stages). The powers are effect kinds of their own, read where they apply: `scienceWild` (Babylon A2 / B3, also the Scientists Guild), `buildFromDiscard` (Halicarnassus), `playLastCard` (Babylon B2), `freeBuildPerAge` (Olympia A2), `copyGuild` (Olympia B3); `builtStageEffects` / `hasWonderPower` read a city's built stages.
- Resources: `resources.ts` — one payment engine for everything. Production (`productionFor`): board, stages, cards, Secret Warehouse / Black Market (a choice among what the board + brown / gray cards make / don't), the Babel free-resource tiles and rules (`productionRules`: no double browns, unlimited single browns, trading posts off), `unlimited` resources. Neighbours sell their wonder's starting resource + brown / gray cards (`sellableProductionFor`), never yellow, black or stage production. Prices: 2, 1 with a trading post / Marketplace / Olympia B, ± the Babel tiles (`tradePrice`, floored at 0), then Clandestine Docks take 1 off the first unit bought from their side (`tradeCoins`). A payment (`SwPayment`) may also leave `waived` units unpaid (Leaders' one-resource-less: `cost.waivable`, restricted to the card's own units by `waivableFrom` when a Great Project participation rides along) and buy one `bank` unit for 1 coin (Bilkis). `planPayment` tries every waive choice and bank unit, then the cheapest split (exhaustive, pruned) — used by the UI and the AI. `effectiveCostFor` applies the city's own discounts (`costDiscount`, `freeGuildResources`, `freeWonderResources`, `freeLeaders`, Rome's `leaderRebate` — the neighbours' too) and then the expansions' `modifyCost` (Babel taxes and free-resource tiles; a chain build is target `chain`, from an empty cost). `canChainBuild(state, …)` also asks `chainSources` (Babel tile 7).
- Scoring: `scoring.ts` — 7 categories. Wild symbols and masks (each copies the symbol of a different green card in a neighbouring city; `scienceHoldings`) go wherever `bestScience` scores most; set bonuses (Aristotle, Babel's science token) add to the 7 per set. `cardVps` scores one card (vp, endVp counts — cards, stages, defeats, victory tokens, recruited leaders, coin sets — and `scoreRule`s). Olympia B copies the neighbour guild that adds the most (`row.copiedGuild`). `rankRows`: most VP, then most coins, else a shared win. `scoreMatch` calls active expansions' `scoreExtras(state, player)` to populate `row.extras` (e.g., `{ leaders: 12 }`).
- Reducer: `reducer.ts` — simultaneous picks via `pendingPick`, validated against the table at the start of the turn; `revealAndApply` places every pick and pays costs (trade coins included), then activates on-play income and events. End of turn (`continueTurnEnd`): the end-of-turn steps in `order` — Leaders' Courtesans' Guild / Rome B (10) and Solomon (15), Halicarnassus' `discardBuild` (20; `discardBuildQueue`, action `buildFromDiscard`, null = pass, optionally joining the Great Project; on the last pick the Age's last cards are already in the pile), Cities' coin losses (30), Babel tiles onto the tower (40); a step that needs a decision sets its sub-phase and the step re-runs after the answer — then the next pick, Babylon B's last card (one more pick, only cities with cards owe one), or the Age's end (expansions' `ageEndStep` — Great Projects — then military). The Recruitment phase (`turnKind: 'leader'`) runs the same steps, then deals the Age. Coins from the bank go through `gainFromBank` (Berenice's +1 once a turn); on-play effects through `applyPlayEffects` (coins, per-count coins, the neighbours' share, coin losses into `pendingLosses`, diplomacy). Military (`resolveMilitary`): `conflictSkips` (diplomacy) — neighbours face each other across the gap, two left fight once —, `victoryToken` / `defeatTokens` (Babel tiles 19 / 22), Tomyris' defeats go to the victor, Semiramis counts defeats as shields (`shieldsFor`). Olympia A: `pick.free`, once per Age (`player.freeBuildUsedAge`). `activePlayerId` during `picking` points at the next seat owing a pick (`nextSimultaneousSeat`) — AIs first, humans first (hot-seat hand-off) when two or more share the device, so no hand is on screen during an AI tick; the view also hides a locked-in hand then (`sharedDeviceHumans`). Online (no seat `isLocal`) the AIs always go first and your own hand stays visible. Leaders' `leaderDraft` / `leaderPlay` park the same way (its `nextAIPicker`), and Solomon's pick on the picker, human or AI. Unknown action types are routed through `getActiveExpansions(config)` so each expansion owns its own subphases + actions. A leader buried under a stage gets the stage's full effect (`applyStage`).
- UI: each neighbour strip says what that city did last turn (read off the log: built X / a stage / sold a card — sold and tucked cards stay unnamed), and cards / stages built on it pop in and glow (CSS, reduced-motion aware). The status bar names who you pass to.
- Art: `art.tsx` — flat hand-drawn SVG, no `<defs>`. ### Set module notes

Rebuilt from scratch (reference implementation: the local `../setwithfriends/` project, which is React + Firebase; no code was ported) so that custom drilling modes can be added and the whole thing hosts statically.

- **Cards are vectors.** `traits.ts` defines `TraitAxis` and two implementations: `Mod3Axis` (3 variants → 1 coordinate mod 3) and `Klein4Axis` (4 variants → 2 coordinates mod 2, i.e. the Klein four-group). `cards.ts`'s `CardSpace` concatenates the axes into a coordinate vector, and `CardId` is the digit string (`"1202"`) — compact, JSON-safe, usable as a map key. Axis order is fixed: colour, shape, shading, border, count (count always last; traits drop from the middle as `traitCount` shrinks).
- **Rules are linear algebra.** `rules.ts`: `ZeroSumRule(n)` = n cards whose vectors sum to zero — `n=3` over Z_3 is Set ("all the same or all different" ⟺ `a+b+c ≡ 0 mod 3`), `n=6` is GhostSet, `n=4` over Z_2 is 4Set (AAAA / ABCD / AABB ⟺ XOR = 0). `PairSumRule(2)` = four cards splittable into two pairs with equal sums = UltraSet. `CardSpace.completion()` (solve for the missing card) replaces the reference's two separate conjugate helpers and makes searches cheap: a zero-sum search picks `size-1` cards and looks the last one up; UltraSet buckets pairs by completion for O(board²) instead of O(board³).
- **Modes are data.** `modes.ts` holds all 16 specs (`family`, `traitCount`, `variants`, `chain`, `puzzle`, `shuffle`, `faceDown`, `minBoardSize`) and `ModeEngine` compiles a spec into space + rule + the anchored/excluded searches. `engineFor(id)` is memoised. **This registry is the seam for new drill modes** — a drill should be a new spec (plus, if it needs one, an objective field the reducer reads), not a new reducer branch. Adding a 6th feature or a `Mod5Axis` is likewise data-only.
- **Board model.** `board.ts`: the board is a window on the deck (`deck.slice(0, boardSize)`). `findBoardSize` grows by rows of three until a legal group exists; `removeFromBoard` back-fills holes inside the protected prefix from beyond it so surviving cards keep their on-screen position. `shufflePrefix` reshuffles only the face-up cards (Shuffle mode), drawing from `state.rngState`.
- **Selection lives in state.** A click is `toggleCard`, and the reducer resolves the group the moment the selection reaches `rule.size` — score / mistake / timing split / board advance all in one pure place. `activePlayerId` is always `null`. Wall-clock time is folded into the action payload (`atMs`), the same way player-chosen randomness is elsewhere, so `applyAction` stays pure.
- **Stats are session-only** (`stats.ts`, derived from `state.history`): split times per find, accuracy, best/median, plus a split-time bar chart on the game-over panel. Nothing is persisted — the "no saves between sessions" non-goal stands.
- **Art is hand-drawn** in `art.tsx`: four shape paths (squiggle / oval / diamond / hourglass), stripe + checker fills via masks (so the ink colour stays a plain `fill`), three border styles for MegaSet's fifth feature, four inks. A single hidden `<defs>` block is mounted by `SetArtDefs` and every card `<use>`s it. Note: symbols are sized inside an absolutely-positioned row (`inset` on `.set-card-symbols`) — an in-flow percentage height would depend on the card's content height, which is the symbols, and collapses them.
- **Shared screen:** 1–4 seats, all human. With more than one seat, the finder picks their name (or presses its number) so the claim is credited to them; `claimantId` tracks it and a mid-selection switch resets the selection. Single-seat play never shows any of this.
- **NOT modelled:** online play (see `onlineSupported: false` and "Set online racing" below), AI/bot opponents, and Kyle's own drill modes.
